# 15. GUI電卓

## 目的
これまでのウィジェット・イベント処理の知識を組み合わせ、状態管理を伴う
実用的なGUIアプリケーション（電卓）を作る。

## 学習ポイント
- ボタン入力の集約と状態管理（入力中の数値、演算子、計算結果）
- 四則演算・小数点・クリアなどのロジック設計
- UIとロジックの分離（表示更新とビジネスロジックを分ける）

## 推奨ライブラリ/ツール
- Qt6 または wxWidgets

本課題では**Win32 API**を採用する。理由はルート [README.md](../README.md#guiライブラリの選定について) を参照。

## 成果物イメージ
数字ボタン・演算子ボタン・イコール/クリアボタンを備え、四則演算ができる
デスクトップ電卓アプリ。

## ビルド方法・実行方法

他の課題と同様にCMakeを使う（詳細はルート [README.md](../README.md#cmakeとvisual-studioの使い分け) を参照）。

```sh
# 15_CalculatorApp ディレクトリで実行
cmake --preset x64-debug
cmake --build --preset x64-debug
./out/build/x64-debug/CalculatorApp
```

## 構成と学習ポイントとの対応

| ファイル | 内容 | 学習ポイント |
|---|---|---|
| `include/calculator.h`/`src/calculator.cpp` | `Calculator`クラス。入力中の数値・保留中の演算子・結果を状態として保持し、四則演算・小数点・クリア・ゼロ除算エラーを実装 | 状態管理、四則演算・小数点・クリアのロジック設計 |
| `src/main.cpp` | 数字/演算子/C/=ボタンをグリッド配置し、`WM_COMMAND`で`Calculator`のメソッドを呼び出して表示欄を更新するだけ | UIとロジックの分離 |

`Calculator`クラスはWin32に一切依存しないため、GUIを介さず単体でインスタンス化して
動作確認できる。

## 動作確認

`Calculator`クラス単体を対象に、一時的な検証用コンソールプログラム（本リポジトリには
含めていない）で以下をすべて確認した。

- `2+3=` → `5`、`7*8=` → `56`
- 小数点を含む計算: `1.5+2.5=` → `4`
- 連続演算: `2+3+4=` → `9`（`+`を押すたびに直前の演算が確定される）
- ゼロ除算: `5/0=` → `Error`、その後`Clear`で`0`に復帰

GUI側は、実行してウィンドウ・全ボタン・表示欄が正しいコントロールIDで作成されている
ことを構造的に確認した。また、`WM_COMMAND`ハンドラ内に一時的なデバッグ出力を仕込んで
検証したところ、ボタンクリックのたびに`Calculator`が正しく呼び出され、`Display()`が
期待通りの文字列を返し、`SetWindowTextW`も成功(戻り値TRUE)することを確認済み。
一方で、外部の自動化スクリプトからのクロスプロセス`GetWindowText`による表示欄の
読み取り確認は、本開発環境では期待通りに動作しなかった（#10で確認した環境固有の
制約と同種の事象）。
