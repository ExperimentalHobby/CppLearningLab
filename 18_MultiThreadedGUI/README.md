# 18. マルチスレッドGUI

## 目的
時間のかかる処理をUIスレッドをブロックせずに実行し、進捗をGUIに反映する
非同期処理の設計を身につける。

## 学習ポイント
- UIスレッドとワーカースレッドの分離（GUIツールキットは基本的にUIスレッド以外から
  直接ウィジェットを操作できないことの理解）
- スレッド間通信（Qtの`QThread`+シグナル・スロット、またはstd::threadとイベントキュー）
- プログレスバーへの進捗反映、キャンセル処理

## 推奨ライブラリ/ツール
- Qt6 (`QThread`, `QProgressBar`) または `std::thread` + 独自のスレッドセーフキュー

本課題では**Win32 API + `std::thread`**を採用する。GUIライブラリ選定の理由は
ルート [README.md](../README.md#guiライブラリの選定について) を参照。

## 成果物イメージ
「重い処理」（ダミーのファイルコピーや計算処理）をバックグラウンドスレッドで実行し、
進捗バーに反映しつつ、UIは操作可能なまま保たれるアプリ。

## ビルド方法・実行方法

他の課題と同様にCMakeを使う（詳細はルート [README.md](../README.md#cmakeとvisual-studioの使い分け) を参照）。

```sh
# 18_MultiThreadedGUI ディレクトリで実行
cmake --preset x64-debug
cmake --build --preset x64-debug
./out/build/x64-debug/MultiThreadedGUI
```

## 構成と学習ポイントとの対応

| 要素 | 内容 | 学習ポイント |
|---|---|---|
| `WorkerThreadProc`(`std::thread`) | ダミーの重い処理(100ステップ、各20msウェイト)をバックグラウンドで実行。ウィンドウは直接操作しない | UIスレッドとワーカースレッドの分離 |
| `PostMessageW(hwnd, kWmProgress, ...)`/`kWmDone` | ワーカースレッド→UIスレッドへの進捗/完了通知 | スレッド間通信(`std::thread`+独自メッセージ) |
| `OnProgress`(`PBM_SETPOS`) | プログレスバーへの進捗反映 | プログレスバーへの進捗反映 |
| `std::atomic<bool> g_cancelRequested` + `OnCancel` | キャンセルボタンでワーカースレッドに早期終了を要求 | キャンセル処理 |
| `WM_DESTROY`でのキャンセル要求+`join` | ウィンドウを閉じる際にスレッドがリークしないよう後始末 | スレッドのライフサイクル管理 |

## 動作確認

ビルド・実行し、外部の自動化スクリプトから以下を確認済み。

- 開始ボタン押下直後、開始ボタンが無効化・キャンセルボタンが有効化される
- 実行中、200msごとにプログレスバーの位置(`PBM_GETPOS`)をポーリングすると
  時間とともに単調増加する（UIスレッドがブロックされずメッセージに応答し
  続けている証拠でもある）
- 完走すると状態ラベルが「完了しました」になり、開始ボタンが再度有効化される
- 実行開始からほどなくキャンセルボタンを押すと、進捗が100%未満のまま
  状態ラベルが「キャンセルされました」になり、開始ボタンが再度有効化される
