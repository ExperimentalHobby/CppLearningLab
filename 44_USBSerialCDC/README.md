# 44. USBシリアル(CDC)通信

## 目的
USB CDC(Communications Device Class)により作成される仮想COMポート経由の
通信を実装し、USBデバイスとシリアル通信(35番)の橋渡しを理解する。

## 学習ポイント
- USB CDCクラスの概要(仮想COMポートとして認識される仕組み)
- 35番のシリアル通信コードをUSB CDCデバイスに対して適用する
- ボーレート等の設定がUSB CDCでは形式的な意味しか持たない場合があることの理解

## 採用ライブラリ/ツール
- Windows API(`CreateFile`等)。35番の`SerialPort`クラスをそのまま使う。
  USB CDCデバイスはOSからは通常のCOMポートとして認識されるため、シリアル
  ポート用のコードがそのまま適用できる。

## 成果物イメージ
Arduino等をUSB CDCデバイスとして接続し、PC側から文字列を送信して
デバイス側からの応答を受信するプログラム。

**本開発環境にはArduino等のUSB CDCデバイスが接続されていないため、
実際の送受信は未確認**(詳細は「動作確認・環境上の制約」を参照)。

## ビルド方法・実行方法

```sh
# 44_USBSerialCDC ディレクトリで実行
cmake --preset x64-debug
cmake --build --preset x64-debug
./out/build/x64-debug/USBSerialCDC <COMポート名> [ボーレート(既定9600)]
```

起動後、標準入力から1行入力するたびにその内容をポートへ送信し、応答を
最大3秒待って表示する(空行で終了)。

## 構成と学習ポイントとの対応

| 要素 | 内容 | 学習ポイント |
|---|---|---|
| `serial_port.h`/`.cpp` | 35番からそのままコピー(`CreateFileW`/`SetCommState`等) | USB CDCデバイスがOSから見て通常のCOMポートと同じAPIで扱えること |
| `main.cpp`の対話ループ | 1行送信→応答受信を繰り返す | コマンド送信→応答受信という一往復のプロトコル(45番の前段) |

## 動作確認・環境上の制約

35番と同様、本開発環境にはArduino等のUSB CDCデバイスが接続されておらず、
「文字列を送ってデバイスから意味のある応答が返る」という成果物イメージ通りの
動作は確認できない。代わりに、35番のREADMEに記載されている実在するCOMポート
(`COM1`)を使い、以下を確認した。

- `COM1`(115200bps)への接続に成功すること
- 文字列の送信(`Write`)がエラー無く完了すること
- 応答が無い状態で約3秒後に正しくタイムアウトし、ハングしないこと
- 存在しないポート(`COM99`)を指定すると、`エラー: ポートを開けませんでした(COM99):
  エラーコード=2 (指定されたファイルが見つかりません。)`が表示されること

実際のUSB CDCデバイスとのコマンド-応答のやり取りは、実機のArduino等を
接続できる環境で改めて確認する必要がある。
