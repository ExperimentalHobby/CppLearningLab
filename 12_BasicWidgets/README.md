# 12. 基本ウィジェット

## 目的
ボタン・ラベル・テキストボックスなどの基本ウィジェットと、レイアウト管理、
メニュー/ツールバー/ステータスバーといったアプリの骨格となるUI要素を扱えるようになる。

## 学習ポイント
- ボタン、ラベル、テキストボックス、チェックボックスなどの基本ウィジェット
- レイアウトマネージャ（垂直/水平/グリッドレイアウト）
- メニューバー、ツールバー、ステータスバーの追加

## 推奨ライブラリ/ツール
- Qt6 (`QPushButton`, `QLabel`, `QLayout`系, `QMenuBar`, `QToolBar`, `QStatusBar`)

本課題では**Win32 API**を採用する。理由はルート [README.md](../README.md#guiライブラリの選定について) を参照。

## 成果物イメージ
複数のウィジェットをレイアウトで整列させ、メニューとステータスバーを備えた
簡単な「設定画面」風のウィンドウ。

## ビルド方法・実行方法

他の課題と同様にCMakeを使う（詳細はルート [README.md](../README.md#cmakeとvisual-studioの使い分け) を参照）。

```sh
# 12_BasicWidgets ディレクトリで実行
cmake --preset x64-debug
cmake --build --preset x64-debug
./out/build/x64-debug/BasicWidgets
```

## 構成と学習ポイントとの対応

| 要素 | 内容 | 学習ポイント |
|---|---|---|
| `STATIC`/`EDIT`/`BUTTON`(`BS_PUSHBUTTON`)/`BUTTON`(`BS_AUTOCHECKBOX`) | ラベル・テキストボックス・ボタン・チェックボックス | 基本ウィジェット |
| `LayoutControls()`（`WM_SIZE`ハンドラから呼び出し） | ツールバー/ステータスバー分を除いた領域に4つのコントロールを縦に配置 | レイアウトマネージャ（Win32には無いため手動実装） |
| `CreateMenu`/`AppendMenu` | ファイル/ヘルプメニュー | メニューバー |
| `TOOLBARCLASSNAME`（comctl32） | テキストのみのツールバー（新規/開く/保存） | ツールバー |
| `STATUSCLASSNAME`（comctl32） | ステータスバー、操作結果の表示 | ステータスバー |

## 動作確認について

ビルドし、実行してプロセスが起動・維持されること、ウィンドウ・全コントロール
（ラベル/テキストボックス/ボタン/チェックボックス/ツールバー/ステータスバー）が
正しいクラス名・コントロールIDで作成されていることを`EnumChildWindows`で確認した。

一方、外部の自動化スクリプト(PowerShell)から`SendMessage`で子コントロールへ
`WM_SETTEXT`等を送りテキストを読み書きする検証は、本開発環境では期待通りに
動作しなかった。トップレベルウィンドウのタイトルに対する`WM_SETTEXT`（外部から
送信→`GetWindowText`で読み出し）は成功する一方、全く同じ手法を子ウィンドウ
（`EDIT`コントロール等）に対して行うと、送信自体は成功扱い(戻り値1)になるにも
関わらずテキストが反映されない、という再現性のある差異が確認された。原因は
特定できていないが、本開発環境（サンドボックス化されたホスト）における
子ウィンドウへのクロスプロセスメッセージ配送固有の制約と考えられ、アプリ側の
実装（`WM_COMMAND`ハンドラでの`GetWindowText`/`SetWindowText`呼び出し）は
Win32の標準的なイディオムに沿っている。この制約はGUI課題(#9〜#16)に共通するため、
以降の課題では同様の構造検証（コントロールの存在確認）とコードレビューを
基準として進める。
